# MicMe comparison: what Pi Dictation should adopt, and in what order

## Executive conclusion

Pi Dictation should **first add a minimal GitHub Actions CI workflow that runs its existing `npm run check` and `npm run pack:check` commands on every push and pull request**. This is the best first change because the current package already has meaningful type, lifecycle, cleanup, crash-watchdog, and UI tests, but the current HEAD has no automated workflow to run them. MicMe's strongest transferable practice is not its larger feature set; it is the release discipline that continuously runs typechecking, runtime loading, tests, lint/format checks, and a package-content guard before publication. [Pi Dictation package scripts](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/package.json#L28-L33) · [Pi Dictation test sources](https://github.com/yasuhito/pi-dictation/tree/163630b7a91d188d7bdcf47e05cfeef3715b36e4/test) · [Pi Dictation HEAD tree](https://github.com/yasuhito/pi-dictation/tree/163630b7a91d188d7bdcf47e05cfeef3715b36e4) · [MicMe CI](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/.github/workflows/ci.yml#L1-L51) · [MicMe validation scripts](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/package.json#L57-L71)

After CI, the highest-value MicMe ideas are a privacy-safe doctor command, bounded configuration with a JSON Schema/example, silence validation, and only then an interactive settings UI. Pi Dictation should not trade away its OpenAI-compatible option, truthful live-level history, explicit cancel command, process-group termination, or independent recording watchdog to copy MicMe's local-only product posture or direct-child process handling. [Pi Dictation backends and safety](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/README.md#L55-L140) · [Pi Dictation lifecycle code](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/extensions/pi-dictation.ts#L638-L877) · [MicMe process stopping](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/src/processes.ts#L55-L94)

## Ideas Pi Dictation should not adopt now

1. **Do not replace the OpenAI-compatible backend with a local-only policy.** MicMe's local-first default is a coherent product choice, but Pi Dictation already supports both private local commands and a simple managed endpoint. Removing either path would reduce user choice rather than improve implementation quality. [Pi Dictation backend docs](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/README.md#L55-L92) [MicMe local-first statement](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/README.md#L19-L37)

2. **Do not copy automatic model downloads yet.** MicMe's implementation needs shared-download ownership, inactivity timeouts, cancellation, partial-file cleanup, model discovery, translation-aware fallback, UI integration, and extensive tests. That is a subsystem, not a small backend addition. [model source](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/src/models.ts) [model tests](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/test/models.test.mjs) [security disclosure](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/SECURITY.md#L51-L66)

3. **Do not adopt experimental streaming before clip-mode setup is easier.** MicMe's append-only streaming handles overlapping hypotheses, tentative word agreement, quiet-period flushes, optional clip replacement, and failure fallback. It also requires `whisper-stream`. Pi Dictation would gain more users per unit effort from diagnostics, schema, silence validation, and settings first. [MicMe streaming docs](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/README.md#L189-L211) [streaming source](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/src/streaming.ts) [streaming tests](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/test/streaming.test.mjs)

4. **Do not replace whole-process-group cleanup with direct child termination.** Pi Dictation deliberately creates detached process groups and verifies descendant cleanup after abrupt Pi death. MicMe's generic runner calls `child.kill(...)` on the direct process and its recorder spawn is not detached. [Pi group signaling](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/extensions/pi-dictation.ts#L210-L267) [Pi abrupt-death test](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/test/pi-dictation.test.cjs#L386-L425) [MicMe spawn/stop](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/src/processes.ts#L9-L94)

5. **Do not copy MicMe's decorative waveform.** MicMe measures a current level but renders a time-shifted sine envelope across 13 bars. Pi Dictation instead renders recent measured intervals and explicitly falls back to a flat silent line when it cannot derive amplitude. The latter is more truthful. [MicMe waveform](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/src/recording-widget.ts#L32-L52) [Pi Dictation strip](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/extensions/pi-dictation.ts#L479-L571) [Pi terminology](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/CONTEXT.md)

6. **Do not default to auto-submit.** MicMe itself defaults to review-first and makes submission opt-in. Pi Dictation's paste-only behavior is the safer default for dictated coding prompts. [MicMe delivery](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/src/transcript-delivery.ts) [MicMe README](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/README.md#L32-L35) [Pi delivery](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/extensions/pi-dictation.ts#L784-L788)

7. **Do not copy MicMe's narrow Pi peer range without a compatibility policy.** MicMe deliberately constrains peers to `>=0.80.7 <0.81.0` and tests `0.80.7`; Pi Dictation develops against `^0.83.0` but publishes wildcard peers. The useful idea is a tested compatibility contract, not MicMe's historical version interval. [MicMe compatibility](https://github.com/senad-d/micme/blob/99c870934c3ae79add7dc84a59477a391d023209/package.json#L79-L91) [Pi Dictation peers/dev versions](https://github.com/yasuhito/pi-dictation/blob/163630b7a91d188d7bdcf47e05cfeef3715b36e4/package.json#L45-L54)

8. **Do not add maintenance ceremony ahead of automation.** MicMe has CODEOWNERS, issue/PR templates, stale automation, Dependabot, Sonar, and contribution/security policies. Those are useful at its activity level, but Pi Dictation's first missing control is a workflow that runs its existing checks. ## Packaging, catalog, and maintenance interpretation

## Single best first improvement

**Implement candidate A only: a minimal GitHub Actions CI workflow for the checks that already pass locally.**

Recommended first pull request scope:

1. Create `.github/workflows/ci.yml`.
2. Trigger on pushes to the default branch and on pull requests.
3. Grant only `contents: read`.
4. Add concurrency cancellation and a 15-minute job timeout.
5. Use Node `22.19.0`, `npm ci`, `npm run check`, and `npm run pack:check`.
6. Do not add lint, formatting, coverage, publishing, badges, Dependabot, or product behavior in the same change.

This gives every later one-at-a-time improvement an independent acceptance gate while preserving Pi Dictation's current user experience and safety architecture.
